# Аудит Linux с помощью Lynis

[Lynis](https://cisofy.com/lynis/) — open-source сканер безопасности: проверяет настройки системы и выдаёт рекомендации
и общий индекс защищённости (Hardening index). Работает локально, ничего не меняет в системе.

## Установка и запуск

```bash
sudo apt install lynis           # Debian/Ubuntu
sudo lynis audit system          # полный аудит (1–3 минуты)
```

Результаты:
- `/var/log/lynis.log` — подробный лог проверок;
- `/var/log/lynis-report.dat` — машиночитаемый отчёт (`warning[]=`, `suggestion[]=`, `hardening_index=`).

## Как читать отчёт

| Раздел | Что значит |
|--------|-----------|
| `Warnings` | реальные проблемы, разбирать в первую очередь |
| `Suggestions` | рекомендации по улучшению, у каждой есть ID (например `SSH-7440`) |
| `Hardening index` | итоговая оценка 0–100; важна динамика, а не абсолютное число |

Подробности по рекомендации: `sudo lynis show details SSH-7440`.

## Рабочий цикл

1. Запустите аудит и сохраните индекс: `sudo grep hardening_index /var/log/lynis-report.dat`.
2. Выберите 2–3 рекомендации с наибольшей отдачей (SSH, пароли, обновления, файрвол).
3. Примените изменения из этого репозитория:
   - SSH — `configs/sshd_hardened.conf`;
   - ядро — `configs/sysctl_hardening.conf` (проверка: `scripts/check_sysctl.sh`);
   - файрвол — `configs/nftables_baseline.conf`;
   - защита от перебора — `configs/fail2ban_jail.local`;
   - аудит событий — `configs/auditd_rules.rules`.
4. Повторите аудит и сравните индекс.

> Не гонитесь за 100 баллами: часть рекомендаций неприменима к конкретной роли сервера.
> Для каждого пропущенного пункта записывайте причину.

## Задания

1. Выполните базовый аудит чистой виртуальной машины, запишите индекс.
2. Примените три изменения из репозитория и повторите аудит. На сколько изменился индекс?
3. Найдите в отчёте предупреждение, которое вы **не** будете исправлять, и обоснуйте решение письменно.
